# TODO интеграции с API

## Исправлено на фронте

- `ProgramCreate`, `CareerTrackCreate`, `CourseCreate` и `ProgressCreate` требуют `user_id` в body, а `ProgressCreate` также требует `course_id`. Фронт теперь формирует эти поля напрямую перед вызовом generated SDK.
- Progress endpoints на backend падают с датой в ISO-формате с timezone suffix (`...Z`/offset). Фронт нормализует дату перед отправкой в `YYYY-MM-DDTHH:mm:ss`, поэтому `POST /progress` работает.
- Nullable/optional поля новой спеки (`id`, `created_at`, `updated_at`, `role`, `status`, `type`) теперь проверяются перед path params, React keys, датами и role/status labels.
- Для fallback React keys при отсутствии `id` используется `window.crypto.randomUUID()`.
- Импорт программы из CSV/XLS/XLSX обрабатывается как локальная валидация с контролируемой ошибкой, потому что endpoint загрузки файла в OpenAPI отсутствует.

## Исправлено уже на backend/app и будет задеплоина

- `POST /api/v1/auth/refresh` больше не должен падать на сравнении aware/naive `datetime`: проверка срока refresh-сессии теперь нормализует timestamp к UTC.
- `GET /api/v1/programs/` и `GET /api/v1/career-tracks/` теперь явно подгружают `user` перед сериализацией в public-схемы и не пытаются отдать записи без валидного автора, чтобы списки не падали на lazy-load/битых связях.
- `POST /api/v1/programs/{program_id}/copy` теперь возвращает программу с заранее подгруженным `user`; это убирает 500 на сериализации результата копирования.
- Проверка уникальности названия программы для create/update/copy теперь использует строгое совпадение `title == ...`, а не contains-фильтр поиска. Это убирает ложные `409` при копировании.
- Проверка уникальности названия курса внутри программы теперь использует строгое совпадение `title == ... AND program_id == ...`, а не contains-фильтр поиска. Это убирает ложные `409` для названий вроде `Тестовый курс`.

## Остается на backend/API

- На фронте встречался `GET /api/v1/courses/?limit=100 -> 500` после создания курса. Повторная проверка от 2026-06-05 сейчас дает `200`, но лимиты загрузки курсов на детальных страницах и прогрессе уменьшены до `20`, чтобы не провоцировать похожую ошибку пагинации.
- Пререквизиты остаются глобальными связями курса через `/api/v1/courses/{course_id}/prerequisites`, без области конкретной программы или карьерного трека.
- Для программ нет endpoint связи существующего курса с программой. Есть только `program_id` у курса; поэтому привязка существующего курса без копирования/перемещения по-прежнему невозможна на уровне API.
- `POST /api/v1/programs/{program_id}/copy` принимает только `title`; `description` в запросе копирования спецификацией не поддержан.
- Backend должен научиться принимать стандартный ISO datetime с timezone suffix (`...Z`/offset), но на фронте уже стоит workaround с отправкой даты без suffix.
